Findings Summary

Validated findings, at a glance

Each finding below has been reviewed and confirmed. Technical detail and remediation steps are documented in the full assessment report.

IDFindingSecurity domainSeverity
VAPT-01 Host routing weakness exposing internal source materials
Request-handling gap in the platform's proxy layer that could expose internal build artifacts if unaddressed. Network & Infrastructure Security High
VAPT-02 Client-side enforcement of access controls
Some access-control decisions are enforced in the browser rather than validated on the server. Authentication & Access Control Medium
VAPT-03 Missing protective HTTP security headers
The web application is missing standard browser-enforced protections present elsewhere on the platform. Application Hardening & Configuration Medium
VAPT-04 Server and route information disclosure
Response details reveal more platform and routing information than necessary. Information Disclosure & Error Handling Medium
VAPT-05 Inconsistent error handling on API requests
Unexpected requests surface generic server errors instead of a clean, handled response. Information Disclosure & Error Handling Medium
VAPT-06 Unauthenticated exposure of backend health details
A monitoring endpoint discloses more backend infrastructure detail than intended, without authentication. Information Disclosure & Error Handling Medium

Key Security Highlights

What stands out

No critical-severity vulnerabilities were identified across the reviewed platform components.

One high-severity finding was identified and has a clear, low-effort remediation path already scoped.

A recurring theme was identified: some authorization logic is enforced client-side rather than validated by the server.

Remaining findings are configuration-related — inconsistent headers and error handling across services, each straightforward to standardize.

High-Level Recommendations

Where to focus next

01
Immediate priority

Remediate the proxy request-handling weakness

Address the single high-severity finding first — it carries the most direct risk of the six findings identified.

02
Near term

Move access-control enforcement fully to the server

Ensure authorization and permission decisions are validated server-side, not only within client-side application code.

03
Near term

Align security headers and error-handling behavior consistently across the web application, gateway, and backend services.

04

Confirm each finding is fully resolved with a targeted re-test prior to the next release cycle.

Assessment Summary

A concentrated, addressable set of findings.

This assessment validated six findings across the Vanij Platform — one high severity and five medium severity, with no critical or low-severity issues identified. The overall risk picture is driven primarily by a single proxy-routing weakness, alongside a consistent pattern of authorization logic that should be enforced server-side and configuration inconsistencies across services.

With the highest-priority item remediated and access-control and configuration standardization completed, the platform's security posture will be materially strengthened. A targeted re-test is recommended to confirm resolution ahead of the next release.
